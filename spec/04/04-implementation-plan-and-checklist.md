# 04 - 分阶段实施计划与验收清单

## 1. 实施阶段

## 阶段 A：模型与存储落地

目标：先把“共享消息 + 房间配置 + 轮次状态”数据底座建好。

工作项：

1. 新增 `src/lib/room/types.ts` 与常量定义。
2. 扩展 `src/lib/storage/db.ts` 到 `DB_VERSION = 3`，创建 room 相关表。
3. 新增 `src/lib/room/storage/*` CRUD 模块。
4. 新增共享消息过滤器 `message-share-filter.ts`（排除 reasoning）。

验收：

1. 可以创建 room、保存角色与编剧提示词。
2. 可以写入/读取共享消息。
3. reasoning 不落库。

## 阶段 B：后端状态机与 API

目标：能在后端完成串行轮转与 100 轮编剧介入。

工作项：

1. 新增 `src/app/api/room/route.ts` 与 `handler-room.ts`。
2. 实现 `RoomEngine`（`character_turn / playwright_review`）。
3. 实现 `turn-policy` 与 `playwright-policy`。
4. 接入 `streamText`，按轮把输出写入共享池。
5. 增加房间级互斥锁。

验收：

1. 连续触发 101 轮时，第 101 轮为编剧修订阶段。
2. 角色始终按串行顺序发言。
3. 并发请求同 room 会被拒绝或排队，不出现乱序写入。

## 阶段 C：前端交流室 UI

目标：把共享消息与提示词控制面板完整展示。

工作项：

1. 新增 `src/app/room/[roomId]/page.tsx`。
2. 新增 `src/components/room/*` 组件。
3. 渲染多角色聊天气泡（角色名 + 内容）。
4. 渲染编剧控制面板与角色提示词编辑器。
5. 展示“距编剧介入剩余轮次”。

验收：

1. 聊天区可看到不同角色名称。
2. 右侧可编辑编剧与角色提示词并保存。
3. 编剧介入后 UI 能看到修订结果。

## 阶段 D：联调与质量收敛

目标：稳定性、可维护性、规范一致。

工作项：

1. 清理重复逻辑，收敛公共类型与转换函数。
2. 补充关键日志与错误提示。
3. 运行 lint 与 tsc 做静态检查。
4. 手工回归：轮转、刷新恢复、异常重试。

验收：

1. lint/tsc 通过。
2. 关键流程无阻断错误。
3. 文件职责清晰，无明显跨模块耦合污染。

## 2. 风险清单

1. 上下文窗口过大导致 token 爆炸：需做最近窗口截断与摘要。
2. 编剧输出不稳定：必须要求结构化输出并做 schema 校验。
3. 房间并发写入：必须保证 room 级锁，否则 turnNo 会错乱。
4. 角色风格收敛：需定期通过编剧修订机制注入差异化人格槽位。

## 3. 验收清单（最终）

1. 共享消息：所有角色读取同一消息池，且 reasoning 不共享。
2. 串行性：任意时刻仅一个角色发言。
3. 编剧机制：每累计 100 次角色发言触发一次编剧修订并继续。
4. 可编辑性：UI 可查看并编辑编剧和角色系统提示词。
5. 展示性：聊天 UI 以角色名称展示发言，支持历史回放。
6. 规范性：无固定色值、日期处理统一 dayjs、依赖 bun。

## 4. 当前阶段建议执行顺序

建议先做 A + B，再做 C：

1. 先把共享消息和状态机跑通，再接 UI，能显著降低前端反复改协议。
2. 编剧修订 JSON 协议先稳定，再开放提示词编辑，避免 UI 回填失败。
