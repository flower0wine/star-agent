请你阅读这个项目，下面是用户需求和任务等。

# 任务

- 深入分析用户需求，你有充足的时间去实现这些需求，你需要制定充足且清晰的规划。
- 目前登录 Github 的实现相对简陋，你需要对其重构优化。
- agent 需要实现可配置的，项目目前并不支持，你需要充分分析该需求，可以选择重构代码来实现。
- agent 的配置分为一些特定的配置项和一些动态的配置项，固定配置例如 star 仓库的拉取方式和附加系统提示词，动态配置如 agent 的工具配置，用户可以自行在所有的 tool 进行挑选。
- 分析项目文件结构，从系统架构角度分析，可以适当重构现有项目以让项目具有前瞻性，易于扩展。

# 需求

- 现在需要优化Github Star 仓库的获取实现，目前的 Star 仓库全部是固定的，因为获取用户的 Star 仓库耗时极长，需要十五秒，所以必须缓存。
- 但是数据又缺少了实时性，但是为了让这个项目足够通用，所以我提出了一个想法。
- 首先项目的目标是制作一个通用多 Agent 平台，目前正在从 star agent 开始试验。
- 然后我的想法是用户可以配置每个 agent，例如可以配置agent可以使用的工具，除了agent固定的系统提示词（因为提示词可以涉及非常多的条件判断和解析），还需要提供用户可以附加的系统提示词等等。
- 这样每个agent可以提供一些固定的配置项，例如上面提到的star仓库的问题，可以在设置页面当中建立一个agent配置页面，每个agent都有其单独的配置，star agent就可以添加一个拉取star 仓库的选项，可以设置为定时拉取等等。
- 除了那些固定的选项，其他的都是可以动态配置的，不是固定的代码配置。

# 代码规范

- 代码应易于维护、模块化且具有易读性。模块、文件等应遵守功能的单一职责原则，避免在同一个文件当中堆砌功能无关的代码。
- 项目文件结构设计需要有架构设计，目录命名具有前瞻性以及功能命名意义，避免无意义，含糊的文件或文件夹命名。
- 将通用代码进行封装，在合适的环节或时机使用设计模式来提高扩展性和可维护性。
- 在合适的时候可以使用设计模式来提高扩展性和代码可维护性，但是避免过度设计。

# 约束

- 颜色不能使用固定的颜色值，使用 Shadcn 自带的颜色值，如果需要使用特定的颜色，需要使用 CSS 变量，这是 tailwindcss 推荐的形式。
- 日期处理使用 dayjs 来处理。
- 包管理器使用 bun。
- 检查错误时使用 lint 和 tsc 来检查。

# 注意

- src\app\layout.tsx 是项目的入口。
- 再创建新的基础 UI 组件前，查看 src\components\ai-elements 和 src\components\ui，已经有许多 UI 组件。ai-elements 是专门用来编写 AI 交互页面的组件，后者是基础组件。
- 不清楚的 API 阅读相关的 Vercel AI SDK 的文档（https://ai-sdk.dev/）以获取相关的 API 参考文档。
- 当遇到方向性问题时需要告知我，比如因为实现困难导致更改方向。但是一些文件命名不需要告知我。
