# 需求

- 分析现有的agent，我想实现一个基座agent，可基于它进行动态配置，它可配置系统提示词，tool等等，并且使用基于CodeMirror来实现系统提示词的编写。
- 将src\components\app\settings\agent-settings\template-variable-textarea.tsx组件提取为通用的组件以适配类似的场景。
- 并且 tool 也可支持动态配置其参数，作为默认值，除非模型给定，否则可以配置参数的默认值。
- 每个 agent 的 每个 tool 配置相互独立，互不干扰。
- 所有的 tool 可以与任意的 agent 搭配，需要提供一个输入框来检索所有可用的 tool。

# 代码规范

- 代码应易于维护、模块化且具有易读性。模块、文件等应遵守功能的单一职责原则，避免在同一个文件当中堆砌功能无关的代码。
- 项目文件结构设计需要有架构设计，目录命名具有前瞻性以及功能命名意义，避免无意义，含糊的文件或文件夹命名。
- 将通用代码进行封装，在合适的环节或时机使用设计模式来提高扩展性和可维护性。
- 在合适的时候可以使用设计模式来提高扩展性和代码可维护性，但是避免过度设计。

# 约束

- 颜色不能使用固定的颜色值，使用 Shadcn 自带的颜色值，如果需要使用特定的颜色，需要使用 CSS 变量，这是 tailwindcss 推荐的形式。
- 日期处理使用 dayjs 来处理。
- 包管理器使用 bun。
- 检查错误时使用 lint 和 tsc 来检查。
- 对代码非常挑剔，你至少会分析并修改三四遍，因为你相信好的代码是通过不断地迭代打造出来的。
