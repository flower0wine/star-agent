# 任务

# 需求

- 需要实现多 Agent 交流室，这些 Agent 共享所有的对话内容，即所有的消息 Agent 都是共享的，但仅限非思考的内容。
- 此外需要有一个单独的 Agent 负责把控全局方向，例如该 Agent 作为编剧，其他的多 Agent 则是这个故事当中的角色。
- 编剧需要编写一个极具丰富的，富有情节跌宕起伏的世界观和具有吸引力的情节，避免陈词滥调的表述和流水线的剧情。
- 每个角色都有其独一无二的性格和特点。
- 角色得到对话是串行的，不能并行，这些角色共享所有的消息，并不是各自保存各自的消息。
- 编剧会在角色对话总计 100 次之后介入，编剧也能看到所有的消息，然后据此分析对话，并调整各个角色的性格和世界观，然后继续开启对话，这些性格和世界观都是 AI 的系统提示词。
- UI 需要体现出编剧掌控全局的感觉，需要展示各个角色的提示词，还有编剧的提示词，但是目前允许编辑。
- 还需要展示多角色的对话，对话使用各个角色的名称，以聊天的UI形式呈现。

# 代码规范

- 代码应易于维护、模块化且具有易读性。模块、文件等应遵守功能的单一职责原则，避免在同一个文件当中堆砌功能无关的代码。
- 项目文件结构设计需要有架构设计，目录命名具有前瞻性以及功能命名意义，避免无意义，含糊的文件或文件夹命名。
- 将通用代码进行封装，在合适的环节或时机使用设计模式来提高扩展性和可维护性。
- 在合适的时候可以使用设计模式来提高扩展性和代码可维护性，但是避免过度设计。

# 约束

- 颜色不能使用固定的颜色值，使用 Shadcn 自带的颜色值，如果需要使用特定的颜色，需要使用 CSS 变量，这是 tailwindcss 推荐的形式。
- 日期处理使用 dayjs 来处理。
- 包管理器使用 bun。
- 检查错误时使用 lint 和 tsc 来检查。
- 对代码非常挑剔，你至少会分析并思考一两遍，必要时进行修改完善，因为你相信优质代码是通过不断地迭代打造出来的。
