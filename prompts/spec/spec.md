请你阅读这个项目，用户想实现一个根据 Github Star 的仓库来进行 AI 问答的 Agent，目的是让用户找到需要的仓库，下面是用户需求和任务等。

# 任务

- 深入分析用户需求，你有充足的时间去实现这些需求，你需要制定充足且清晰的规划。
- 你不需要进行编写实际的代码实现，你只需要进行规划即可。
- 分析完用户需求之后生成对应的文档，分步骤生成执行文档，文档放在 spec 目录下，每一步需要单独生成一个 md 文档，每个 md 文档之间在功能实现无紧密联系。
- 每个 md 文档需要包含需要实现的需求，预期的效果等等，符合软件驱动开发最佳实践，不需要包含具体的代码实现。
- 每个 md 文档将会安排不同的开发者同时进行，所以你需要将不同的功能模块安排给不同的开发者，md 的功能实现之间尽量避免功能重复或交集。
- 你需要编写一个项目目标和项目架构以及规范文档，这个文档将被所有的开发者参考，目的是为了让开发者不偏离项目目标，同时保证开发者编写的代码符合预期和规范。

# 用户需求

- 网页需要获取用户的所有的 Star 仓库，可以使用 OAuth 来请求用户登录。
- 借助 mastra 的 Agent 构建能力实现 AI 功能。
- 避免将所有的 Github 仓库的 README 文档传输给 AI，而是采用渐进式披露逐步获取更多信息。例如开始时仅提供仓库名和一些描述性信息，topic，然后让 AI 分析哪个仓库更符合用户要求，进而查看具体的 README 进行深入分析和匹配。
- 页面分为左侧侧边栏（可选择性关闭）和右侧 AI 交互面板（可提问，查看回答的内容）。
- 侧边栏分为上下两部分，上面是新对话，历史会话记录等等，下面是设置项，亮暗模式调节，关于等等菜单项，菜单栏关闭时显示简洁的图标，悬浮时有 tooltip 提示。
- AI 交互面板尽可能使用 src\components\ai-elements 的组件创建，避免造轮子。
- 项目由于直接使用 Github 数据，所以可能不会使用数据库，仅是一个前端项目，无后端形式，会话记录数据将使用 localstorage 来存储。
- 用户设置同样保存在 localstorage。会话数据和用户设置的存储考虑存储的扩展性，以适配未来的数据库接入的可能性。
- 模型将使用 openrouter 提供的模型来实现 AI 对话。

# 设计规范

- 页面设计简洁，大量留白体现优雅，高端。
- 使用动画实现丝滑过渡，避免出现无动画元素。
- 页面响应流畅，设计规范，符合UI、UX设计最佳实践。
- 无障碍设计符合最佳实践。

# 代码规范

- 代码应易于维护、模块化且具有易读性，模块、文件等应遵守功能的单一职责原则，避免在同一个文件当中堆砌功能无关的代码。
- 项目文件结构设计需要有架构设计，目录命名具有前瞻性以及功能命名意义，避免无意义，含糊的文件或文件夹命名。
- 将通用代码进行封装，在合适的环节或时机使用设计模式来提高扩展性和可维护性。

# 约束

- 使用 Shadcn 组件库来实现目前的需求，目前安装的组件位于 src\components\ai-elements 和 src\components\ui，ai-elements 是专门用来编写 AI 交互页面的组件，后者是基础组件。
- 使用命令来安装对应的组件，而不是自己编写。
- 颜色不能使用固定的颜色值，使用 Shadcn 自带的颜色值，如果需要使用特定的颜色，需要使用 CSS 变量，这是 tailwindcss 推荐的形式。
- 日期处理使用 dayjs 来处理。
- 包管理器使用 bun。

# 注意

- 避免重复造轮子，src\components\ai-elements 和 src\components\ui 下面已经有许多 UI 组件。
